# GitHub Issues Triage 設計

## 設計方針

要求と動作は、[要求定義](REQUIREMENTS.md)と[仕様](SPECIFICATIONS.md)に従う。
本書の責務、依存関係、検証境界は必須 (MUST) とする。
端末 UI は、描画関数と入力ループで構成する。

## モジュールと責務

| モジュール | 責務 |
| --- | --- |
| `cli` | コマンド、リポジトリ名、root 設定引数の検証 |
| `credentials` | OS 資格情報ストアの読み書きと保存形式 |
| `auth` | Device Flow、トークン更新、認証応答の検証 |
| `github` | Issue 取得、ページング、PR 除外、属性検証 |
| `jev` | Jev リクエスト、再試行、判定応答の検証 |
| `model` | 重要度順、Ready、検索、ソート、日付、命名の判定規則 |
| `branch` | root 設定、対象 Git 検証、状態確認、作成と切り替え |
| `presentation` | 一覧、ダイアログ、Unicode、描画と操作領域、JSON |
| `main` | 外部処理の接続、対話状態、入力、端末復元、終了コード |

## 依存関係

- `model` は、端末、HTTP、資格情報ストア、Git に依存しない。
- 検索とソートの判定は、`model` に保持する。
- Git 操作と対象検証は、`branch` に保持する。
- 入力の解釈と画面間の遷移は、`main` に保持する。
- `presentation` は、描画内容とクリック領域を同じ値から作る。

## 主要データ

| データ | 役割 |
| --- | --- |
| `Issue` | 番号、タイトル、本文、一覧用の属性 |
| `RankedIssue` | Issue と検証済みの score、prefix、Ready |
| `IssueSort` | ソート列と方向 |
| `ListState` | ソート、仮選択、一覧の位置 |
| `SearchState` | 適用済み検索語、入力中の検索語、未完 UTF-8 |
| `InputState` | 分割制御列と貼り付けモード |
| `RenderedTable` | 描画文字列、行領域、見出し領域、確認不能理由 |
| `IssueRegion` | 行範囲と仮選択時の描画文字列 |
| `Dialog` | 寸法、位置、本文、固定ボタンとクリック領域 |

取得した Issue の元の集合は、検索で破棄しない。
表示集合を検索とソートで再構築する。
行領域の添字は、同じ表示集合の Issue に対応させる。
セル内スクロール位置と一覧内の作成ボタン領域は保持しない。

## 処理フロー

1. CLI 引数を検証する。
2. 保存済み認証情報を読み取り、認証済みの Issue を取得する。
3. Jev の全回答を検証し、重要度順に並べる。
4. 一覧経路では、ブランチ状態を確認して一覧を描画する。
5. 一覧の入力に応じて、検索、本文、ヘルプを開く。
6. ダイアログの操作は、ダイアログ内で消費する。
7. 検索確定後は、表示集合と行領域を再構築する。
8. 作成ボタンの操作では、表示中の Issue を `branch` へ渡す。
9. 成功後は、一覧へ戻る場合にブランチ状態を更新する。
10. 終了時には、端末の入力と表示を復元する。

`next` は同じ取得と判定を使用し、Ready の候補を JSON にする。
`next` は、対話状態と一覧用の属性を選定条件にしない。

## 描画と状態管理

- 一覧の行高は、折り返した7セルの最大行数とする。
- 仮選択の描画では、対象行のセルだけへ背景色を付ける。
- 描画済みの行領域を、ホバーと本文を開く操作で共有する。
- 見出しクリックを、行クリックより先に処理する。
- 下部3ボタンを、一覧のクリックより先に処理する。
- 一覧のホイールは、一覧全体の位置だけを変更する。
- ダイアログは、共通の枠描画を使って中央へ配置する。
- 本文とヘルプは、固定ボタンを残して内容だけを移動する。
- 検索ダイアログは、内容5行と上下の外枠の計7行で中央配置する。
- 検索は、適用済みの検索語をコピーして入力を開始する。
- 検索の Close は、未確定の検索語と未完 UTF-8 を破棄する。
- 検索の文字入力は、一覧のショートカットを呼び出さない。
- 貼り付けモードと分割受信の状態は、入力待ちをまたいで維持する。
- Enter と Esc の到着時刻を、IME の判定に使用しない。
- 検索確定時だけ、仮選択と一覧の位置をリセットする。
- ソートと再描画では、一覧の位置を移動可能範囲に補正する。

## 外部境界とエラー処理

- HTTP は、30秒のタイムアウトを持つ共通クライアントを使う。
- GitHub の認証失敗と更新失敗は、文脈を分けて伝播する。
- `fetch_authenticated_issues` は、取得、更新、再認証、保存を接続する。
- 保存成功後の再取得は、一度だけ行う。
- Device Flow の interval、expires_in、slow_down は応答に従う。
- Jev は、Score と2種類の Choice を1リクエストへまとめる。
- Jev の回答は、件数、対応、型、範囲、確率の整合性を検証する。
- 429 と529 は、最大3回の試行と上限付きバックオフで再試行する。
- OS 資格情報ストアの失敗を、平文保存へ置き換えない。
- Git の対象検証、main 起点、同名拒否は `branch` が担当する。
- ブランチ状態確認は読み取り専用とし、確認不能理由を一覧へ返す。
- 作成の成功と失敗は、結果ダイアログへ表示する。
- 入出力の失敗は、呼び出し元へ伝播する。
- `TerminalMode` は、正常終了とエラー時の端末復元を担当する。
- Drop は、明示的な復元が完了しなかった場合の復元を試みる。

## 保存とセキュリティ

- 資格情報の service は `gh-issues-triage` とする。
- 資格情報の account は `github.com` とする。
- アクセストークン単体とトークンの JSON を読み取る。
- root 設定には、JSON ファイルを使用する。
- トークンと API キーを、root 設定へ保存しない。
- Issue 本文は判定対象のデータとして扱い、判定指示としない。
- 端末表示の制御文字は、幅計算より前に無害化する。
- JSON では、端末表示の加工をせずにエスケープする。

## 検証境界

- model: AND 検索、ソートの両方向、同値順、Ready、日付境界。
- presentation: 列幅、折り返し、タイトル限定、ハイライト、制御文字。
- Dialog: 寸法、固定ボタン、クリック境界、長文、空本文、幅不足。
- main: 入力の分割受信、貼り付け、検索の確定と破棄、受け付けるキーの制限。
- main: ダイアログ操作の隔離、ホイール上下限、表示対象の対応。
- 外部境界: 認証、資格情報、GitHub、Jev、Git、JSON の動作検証。
- 自動検証には、`make check` と `make build` を使用する。
- 実端末の描画、マウス、IME は、自動検証と分けて確認する。
- 実 GitHub と実 Jev の検証は、自動検証と分けて確認する。
