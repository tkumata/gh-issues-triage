## 処理フロー

### トリアージ

認証方式の詳細な分岐条件は、[仕様の認証](SPECIFICATIONS.md#認証)に従う。

1. アプリケーションは、CLI 引数を検証する。
2. アプリケーションは、認証情報を取得する。
3. アプリケーションは、認証情報の状態に従って認証方式を選ぶ。

   | 条件 | 処理 |
   | --- | --- |
   | 保存済みアクセストークンが有効 | 保存済みアクセストークンを使用 |
   | アクセストークンが失効 | リフレッシュトークンで更新後に保存 |
   | 認証情報が未保存 | Device Flow で認証後に保存 |
   | リフレッシュトークンが存在しない、または失効 | Device Flow で認証後に保存 |

4. アプリケーションは、GitHub REST API から最新の open 状態の Issue を取得する。
5. アプリケーションは、取得対象を最大10件に制限する。
6. アプリケーションは、全 Issue を1回の Jev リクエストで判定する。
7. Jev は、重要度、ブランチ分類、Ready を返す。
8. アプリケーションは、全回答を検証する。
9. アプリケーションは、Issue を重要度順に安定ソートする。
10. アプリケーションは、端末幅に合わせてテーブルを描画する。

## 責務

| 責務 | 内容 |
| --- | --- |
| CLI | 対象リポジトリの検証、使い方の表示、終了コード |
| GitHub 認証 | 保存済みトークンの使用、更新、Device Flow、GitHub エラーの解釈 |
| 認証情報の保存 | 資格情報ストアでのトークンの保存と読み込み |
| Issue の取得 | REST API のページング、プルリクエストの除外、最大10件への制限 |
| トリアージ | Jev リクエストの構築、`Score` と `Choice` の応答検証、安定ソート |
| 表示 | Unicode 表示幅による折り返し、列幅の配分、罫線の描画 |

- 実装者は、責務を識別できるファイル分割の中からファイル数が最少の構成を選ぶ。
- 任意 (MAY): 実装者は、責務ごとにファイルを作成できる。
