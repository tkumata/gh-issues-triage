## CLI

アプリケーションは、次のコマンド形式を受け付ける。

```text
gh-issues-triage <owner>/<repo>
gh-issues-triage config set-root <absolute-directory>
gh-issues-triage --help
```

- `--help` 単独の場合、アプリケーションは次の情報を標準出力へ表示する。
  - Cargo パッケージのバージョン
  - 使い方
  - 各引数の説明
- `--help` 単独の場合、アプリケーションは終了コード `0` で終了する。
- 入力エラーの条件は、次のいずれかとする。
  - 引数が存在しない。
  - サブコマンドが未知である。
  - 引数を `<owner>/<repo>` として解釈できない。
- 入力エラーの場合、アプリケーションは使い方を標準エラー出力へ表示する。
- 入力エラーの場合、アプリケーションは終了コード `2` で終了する。
- アプリケーションは、空文字の `owner` を拒否する。
- アプリケーションは、空文字の `repo` を拒否する。
- アプリケーションは、余分なパス要素を拒否する。
- 処理が成功した場合、アプリケーションは終了コード `0` で終了する。
- 次の処理が失敗した場合、アプリケーションは非ゼロの終了コードで終了する。
  - 入力の処理
  - 認証
  - 通信
  - 応答の処理
  - 保存
  - 表示

## 認証

### エンドポイント

| 名称 | HTTP メソッドと URL |
| --- | --- |
| デバイスコード取得 | `POST https://github.com/login/device/code` |
| トークン取得・更新 | `POST https://github.com/login/oauth/access_token` |

### 保存済み認証情報の使用と更新

- 保存済みアクセストークンが有効な場合、アプリケーションはアクセストークンを使用する。
- 保存済みアクセストークンの用途は、Issue の取得とする。
- アプリケーションは、旧版が保存したアクセストークン単体の値も読み取る。
- 次の条件を両方満たす場合、アプリケーションはトークン取得・更新へ更新要求を送る。
  - アクセストークンが失効している。
  - 保存済みリフレッシュトークンが存在する。
- 更新要求のパラメーターは、次の値とする。
  - `client_id`
  - `grant_type=refresh_token`
  - `refresh_token`
- Device Flow のトークン更新では、アプリケーションはクライアントシークレットを使用しない。
- 更新成功後、アプリケーションは2つのトークンを組として資格情報ストアへ保存する。
- 保存成功後、アプリケーションは新しいアクセストークンで Issue 取得を再試行する。

### Device Flow の開始条件

- 次の条件のいずれかを満たす場合だけ、アプリケーションは Device Flow を開始する。
  - アプリケーションの認証情報が未保存である。
  - アプリケーションのリフレッシュトークンが存在しない。
  - GitHub が `bad_refresh_token` を返す。
  - トークン更新時に GitHub が `incorrect_client_credentials` を返す。
- 更新時の `incorrect_client_credentials` は、トークンの失効と断定しない。
- 同エラーでは、アプリケーションは更新時に拒否された旨を表示する。
- 同エラーでは、アプリケーションは再認証が必要である旨を表示する。
- 案内の出力先は、既存の認証案内と同じとする。
- アプリケーションは、Device Flow を一度だけ開始する。
- Device Flow 自体が失敗した場合、アプリケーションは失敗終了する。
- Device Flow の再認証では、既存の待機間隔と有効期限を使用する。
- 再認証成功後だけ、アプリケーションは新しい認証情報を保存する。
- 再認証前に、アプリケーションは保存項目を削除しない。
- 保存成功後、アプリケーションは Issue 取得を一度だけ再試行する。
- 再取得が失敗した場合、アプリケーションは再認証を繰り返さない。
- Device Flow へ進まない認証エラーは、次の失敗とする。
  - 資格情報ストアの失敗
  - 通信の失敗
  - 上記2種類の OAuth エラー以外の更新エラー
  - 対象リポジトリの権限不足
- Device Flow へ進まない認証エラーでは、アプリケーションは理由を表示する。
- Device Flow へ進まない認証エラーでは、アプリケーションは失敗終了する。
- 更新時の失敗では、エラーに `GitHub token refresh failed` を付ける。
- Device Flow の認証失敗では、`GitHub device authorization failed` を付ける。
- 認証段階の表示には、秘密値を含めない。
- トークン更新が必要な場合、アプリケーションは `GITHUB_CLIENT_ID` を取得する。
- Device Flow が必要な場合も、アプリケーションは `GITHUB_CLIENT_ID` を取得する。
- 更新と Device Flow が不要な場合、アプリケーションは `GITHUB_CLIENT_ID` を取得しない。
- クライアント ID が未設定または空の場合、アプリケーションは失敗終了する。

### Device Flow の処理

1. アプリケーションは、デバイスコード取得へリクエストを送る。
2. アプリケーションは、応答から次の値を取得する。
   - `device_code`
   - `user_code`
   - `verification_uri`
   - `expires_in`
   - `interval`
3. アプリケーションは、`verification_uri` を表示する。
4. アプリケーションは、`user_code` を表示する。
5. アプリケーションは、ブラウザを自動起動しない。
6. アプリケーションは、`interval` 以上の間隔でトークン取得・更新をポーリングする。
7. `authorization_pending` の場合、アプリケーションは待機を継続する。
8. `slow_down` の場合、アプリケーションは GitHub の指示どおり待機間隔を延長する。
9. 認証が成功した場合だけ、アプリケーションはアクセストークンを資格情報ストアへ保存する。
10. 認証成功後、アプリケーションは発行済みリフレッシュトークンを資格情報ストアへ保存する。
11. 保存成功後、アプリケーションは Issue 取得を続ける。

- Device Flow のエラーは、次の失敗とする。
  - 認証の拒否
  - 認証の期限切れ
  - クライアント ID の不正
  - Device Flow の無効化
  - 通信の失敗
- Device Flow のエラーでは、アプリケーションは理由を表示する。
- Device Flow のエラーでは、アプリケーションは失敗終了する。

## `<owner>/<repo>`

### Issue の取得

- アプリケーションは、GitHub REST API の次のエンドポイントを使用する。

```text
GET /repos/{owner}/{repo}/issues
```

- リクエストのパラメーターは、次の値とする。
  - `state=open`
  - `sort=created`
  - `direction=desc`
- 応答項目が `pull_request` フィールドを持つ場合、アプリケーションは項目を除外する。
- 除外後の Issue が100件に達するまで、アプリケーションは後続ページを読み取る。
- open 状態の Issue が100件未満の場合、アプリケーションは存在する件数だけを取得する。
- トリアージには、アプリケーションは `number`、`title`、`body` を使用する。
- `body: null` の場合、アプリケーションは本文なしとして扱う。
- 「最新」は、`created_at` の降順を意味する。

### Jev による重要度

- アプリケーションは、TypeSafe HTTP API の次のエンドポイントを使用する。

```text
POST https://api.typesafe.ai/v1/systemone
```

- アプリケーションは、次の認証ヘッダーを付ける。

```text
Authorization: Bearer <API_KEY>
```

- モデル名は、追従用エイリアス `jev-latest` とする。
- アプリケーションは、取得した最大100件の Issue を1つの構造化状態にまとめる。
- アプリケーションは、Issue ごとに独立した `Score` 質問を1つ作る。
- 判定指示には、対象 Issue の `number`、`title`、`body` のパスを明記する。
- 判定指示には、Issue の重要度を判定する目的を明記する。
- アプリケーションは、質問 ID の値自体に判定の意味を依存させない。
- `Score` の判定基準は、次の5段階を低い順に使用する。

| 段階 | 判定基準 |
| ---: | --- |
| 0 | 対応不要、情報提供のみ、または影響が確認できない |
| 1 | 影響が小さく、容易な回避策がある |
| 2 | 通常機能への影響はあるが、業務は継続できる |
| 3 | 主要機能の妨害、広いユーザーへの影響、または回避困難な問題 |
| 4 | データ損失、セキュリティ、サービス停止など、即時対応が必要な影響 |

- アプリケーションは、API が返す確率加重 `score` を検証する。
- アプリケーションは、検証済みの `score` を変換せず重要度として使用する。
- アプリケーションは、`confidence` を順位計算に使用しない。
- 初期版では、アプリケーションは `confidence` を表示しない。
- 次の失敗では、アプリケーションはコマンド全体を失敗させる。
  - 回答が一部でも欠落する。
  - 回答の型が不正である。
  - TypeSafe の処理が失敗する。
- アプリケーションは、回答の失敗を推測値で補わない。
- HTTP `429` または `529` の場合、アプリケーションは上限付き指数バックオフで再試行する。
- 再試行が上限に達した場合、アプリケーションは失敗終了する。
- 実装者は、再試行回数をテスト可能な定数として定める。
- 実装者は、タイムアウトをテスト可能な定数として定める。

### 並べ替え

- アプリケーションは、初期表示と `next` で重要度降順に安定ソートする。
- 重要度が同じ場合、アプリケーションは GitHub から取得した順序を維持する。

## テーブル

```text
┌─────────┬───────┬─────────┬─────────┬───────────┬─────────────┬──────────┐
│ 重要度↓ │ Ready │ 番号    │ Author  │ Assignees │ 日付        │ Issues   │
├─────────┼───────┼─────────┼─────────┼───────────┼─────────────┼──────────┤

```

- 出力先が端末で幅を取得できる場合、アプリケーションは各行の表示幅を端末幅に合わせる。
- アプリケーションは、固定列を内容と左右の余白が収まる最小幅にする。
- アプリケーションは、残りの幅を `Issues` 列へ割り当てる。
- アプリケーションは、`Issues` 列にタイトルを表示する。
- アプリケーションは、タイトル直後の行から本文を表示する。
- アプリケーションは、入力中の改行を保持する。
- アプリケーションは、各行を列幅で折り返す。
- アプリケーションは、Unicode 表示幅を折り返しの基準にする。
- 折り返した内容は、セル境界を越えない。
- アプリケーションは、Issue ごとに中罫線を置く。
- テーブル表示の端末幅エラーは、次の条件とする。
  - アプリケーションが端末幅を取得できない。
  - 端末幅が7列の表示に足りない。
- 端末幅エラーでは、アプリケーションは失敗の理由を表示する。
- 端末幅エラーでは、アプリケーションは失敗終了する。
- アプリケーションは、取得できない端末幅を根拠のない既定幅で置き換えない。
- Issue が0件の場合、アプリケーションはヘッダーだけの空テーブルを表示する。
- Issue が0件の場合、アプリケーションは成功終了する。

### 一覧の仮選択とスクロール

- マウスが Issue 上にある場合、アプリケーションは Issue を仮選択する。
- マウスが Issue の行範囲外へ移動した場合、アプリケーションは仮選択を解除する。
- ヘッダー、横罫線、ヘルプは、Issue の行範囲に含めない。
- `j` または下矢印の場合、アプリケーションは次の Issue を仮選択する。
- `k` または上矢印の場合、アプリケーションは前の Issue を仮選択する。
- 先頭または末尾に達した場合、アプリケーションは仮選択の移動を止める。
- アプリケーションは、先頭と末尾の間で仮選択を循環させない。
- 仮選択がない場合、アプリケーションは初回の仮選択キー操作で先頭の表示 Issue を選ぶ。
- Issue がまだ表示されていない場合、アプリケーションは一覧の先頭の Issue を選ぶ。
- アプリケーションは、最後のマウス移動または仮選択キー操作を優先する。
- マウスオーバー後のキー操作では、アプリケーションは仮選択中の Issue を移動の基準にする。
- 仮選択した Issue が画面外の場合、アプリケーションは一覧を自動スクロールする。
- Issue が画面より高い場合、アプリケーションは仮選択後に Issue の先頭を表示する。
- PageUp と PageDown では、アプリケーションは一覧を表示領域の行数分スクロールする。
- 上端または下端に達した場合、アプリケーションはスクロールを止める。
- PageUp と PageDown では、アプリケーションは仮選択を維持する。
- アプリケーションは、仮選択した Issue の全セルに次の色を適用する。
  - 背景: bright blue（SGR `104`）
  - 文字: black（SGR `30`）
- 色の適用対象は、余白、タイトル、本文、ブランチ作成ボタンを含む。
- アプリケーションは、ANSI 16色を使用する。
- 実際の色味は、端末のパレットに従う。
- 各縦罫線の直前で、アプリケーションは前景色と背景色を既定色へ戻す。
- アプリケーションは、外枠、縦罫線、横罫線、ヘッダー、ヘルプの色を変えない。
- アプリケーションは、仮選択だけでブランチを作成しない。
- 作成結果画面では、アプリケーションは `j`、`k`、上下矢印で作成結果を1行ずつスクロールする。

## 設定と秘密情報

- アプリケーションは、環境変数 `TYPESAFE_API_KEY` から API キーを取得する。
- アプリケーションは、TypeSafe の API キーを永続保存しない。
- アプリケーションは、環境変数 `GITHUB_CLIENT_ID` からクライアント ID を取得する。
- アプリケーションは、クライアントシークレットを使用しない。
- アプリケーションは、PAT を使用しない。
- アプリケーションは、アクセストークンを資格情報ストアへ保存する。
- リフレッシュトークンの発行後、アプリケーションはリフレッシュトークンを資格情報ストアへ保存する。
- 資格情報ストアの保存先識別子は、次の値とする。
  - サービス名: `gh-issues-triage`
  - アカウント名: `github.com`
- macOS では、アプリケーションは Keychain を使用する。
- Linux では、アプリケーションは Secret Service を使用する。
- 資格情報ストアを利用できない場合、アプリケーションは失敗終了する。
- アプリケーションは、資格情報ストアの代替手段として平文ファイルを使用しない。
- アプリケーションは、秘密情報をエラー本文へ含めない。

## 対象

- アプリケーションの対象サービスは、GitHub.com に限定する。
- アプリケーションの対応 OS は、macOS と Linux とする。
- 対象リポジトリは、GitHub App とユーザーの権限でアクセスできる範囲に限定する。

### 取得と選択

1. アプリケーションは、既存の認証方式で Issue を取得する。

## 追加仕様: 行高制限とセル内スクロール (Issue #39)

### 行高

- `B = 端末高 - 検索欄の行数 - ヘルプの行数 - 重要度説明の行数` とする。
- 検索欄は、入力欄と Search ボタンの1行に、空行1行を加える。
- ヘルプの行数は、Help ボタン1行と確認不能理由の行数とする。
- 高さは、各領域の折り返し後の物理行数を使用する。
- 各行の内容の上限は、整数除算の `B / 3` とする。
- 表示順の先頭から `B % 3` 件の行には、上限を1行加算する。
- 4件目以降は、基準の上限を使用する。
- Issue が3件未満の場合も、除数は3とする。
- 見出しと横罫線は、上限に含めない。
- 3件全体が一画面へ収まることは保証しない。
- 短い行の高さは、最長のセルの内容に必要な行数とする。
- 短い行の未使用分は、他の行へ再配分しない。
- 検索と並べ替え後は、表示順に基づいて余りを配分し直す。
- 一覧に Issue が存在し、`B < 3` の場合は理由を示して失敗終了する。
- 端末サイズは、既存の起動時の取得結果を使用する。
- 端末サイズを取得できない場合、架空のサイズは使用しない。
- 空一覧と検索結果0件の表示は、既存動作を維持する。

### 操作と状態

- ホイールは、ポインター直下のセルだけを1行移動する。
- セルの左右の余白も、ホイールの対象に含める。
- 各セルは、独立したスクロール位置を持つ。
- セルの先頭と末尾では、スクロールを停止する。
- セルの端に達しても、一覧全体へ操作を転送しない。
- 罫線、見出し、検索欄、ヘルプ上のホイールは無視する。
- キー操作は、セル内の位置を変更しない。
- `j`、`k`、上下矢印は、既存の Issue 単位の仮選択を維持する。
- PageUp と PageDown は、既存の一覧全体の移動を維持する。
- 検索と並べ替えでは、全セルの位置を先頭へ戻す。
- ブランチ作成結果から戻る場合は、全セルの位置を維持する。
- 作成ボタンは、`Issues` セルの末尾の内容としてスクロールする。
- 表示中のボタン断片だけを、クリック対象にする。
- 数字キーによる既存のブランチ作成操作は維持する。
- Unicode の幅計算、折り返し、制御文字対策を維持する。
- `next` の経路へ、行高やセル位置の状態を渡さない。
