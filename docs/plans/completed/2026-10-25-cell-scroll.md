## Goal

長い Issue が一覧の表示領域を占有する問題を解消する。
ユーザーは、高さを制限したセル内で内容を読み進められる。
セル内のスクロール操作は、マウスホイールに限定する。

## Scope

- 対話型の Issue 一覧の行高計算と描画。
- マウスホイールの入力解析とセルの座標判定。
- セル内のスクロール位置と一覧のスクロール位置の管理。
- 検索、並べ替え、仮選択、ブランチ作成との接続。
- `src/main.rs`、`src/presentation.rs` と同ファイル内のテスト。

## Required Behavior

### Issue 本文で指定された要求

以下の要求は必須 (MUST) とする。

- アプリケーションは、Issue 一覧の各行の高さに上限を設ける。
- 上限を超える内容は、セル内でスクロールして表示する。
- セル内のスクロール操作は、マウスホイールだけを使用する。
- キーボード操作は、セル内のスクロール位置を変更しない。
- 行高の基準値は、次の式で算出する。
- 除算の余りは、他のテーブル行へ配分する。
- 本変更は、`next` の経路へ関与しない。

```text
(ターミナルの高さ - 検索行 - ヘルプ行 - 重要度説明行) / 3
```

### 変更前の状態

- `render_issue` は、折り返し後の最長セルに行高を合わせる。
- `Issues` セルは、タイトル、本文、ブランチ名、作成ボタンを含む。
- `parse_mouse_event` は、クリックとマウス移動だけを扱う。
- `j`、`k`、上下矢印は、Issue の仮選択を移動する。
- PageUp と PageDown は、一覧全体をスクロールする。
- 重要度説明は、現在のテーブル文字列に含まれる。
- ヘルプは、操作案内とブランチ状態の凡例を含む。
- 検索欄、ヘルプ、凡例は、複数の物理行を使用する。
- `next` は、一覧の描画と操作処理を呼び出さない。

### 承認済み仕様

以下は、2026-10-25 にユーザーが承認した仕様である。
要求レベルは、必須 (MUST) とする。

- 高さの計算は、折り返し後の物理行数を使用する。
- ホイールの対象は、ポインター直下のセルとする。
- 各セルは、独立したスクロール位置を保持する。
- ホイールの上下1イベントにつき、内容を1行移動する。
- セルの先頭と末尾では、スクロール位置を固定する。
- セルの端に達しても、一覧全体へスクロールを転送しない。
- 罫線、見出し、検索欄、ヘルプ上のホイールは無視する。
- 短い行の高さは、内容に必要な高さまでとする。
- 短い行の未使用分は、他の行へ再配分しない。
- `j`、`k`、上下矢印の仮選択操作を維持する。
- PageUp と PageDown の一覧全体のスクロールを維持する。
- 検索または並べ替えでは、セル内の位置を先頭へ戻す。
- ブランチ作成結果から戻る場合、セル内の位置を維持する。
- 作成ボタンは、既存の `Issues` セル内の内容として扱う。
- 画面に見えるボタンだけを、クリック対象にする。
- 数字キーによる既存のブランチ作成操作を維持する。
- 描画、仮選択、ボタンの座標は、同じ表示領域を参照する。
- 日本語の折り返し、制御文字対策、端末復元を維持する。
- 表示に必要な高さがない場合、理由を示して失敗終了する。
- 高さを取得できない場合、架空の端末サイズを使用しない。
