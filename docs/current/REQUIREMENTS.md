# GitHub Issues Triage 要求定義

## 目的

GitHub リポジトリの直近の Issue を、人が最初に確認すべき順へ並べてターミナルに表示する。

## 対象ユーザー

- GitHub リポジトリの Issue を CLI から短時間で確認したい開発者

## 機能要求

### 認証

- `gh-issues-triage login` は GitHub App の Device Flow を開始する。
- CLI は確認 URL とアクセスコードを表示し、ユーザーによるブラウザ認証の完了を待つ。
- 認証成功後、後続の実行で利用できるよう認証情報を保存して終了する。
- GitHub App の client ID は `GITHUB_CLIENT_ID` 環境変数から取得する。
- GitHub App user access token は OS の資格情報ストアへ保存する。
- PAT と平文ファイルへの fallback は使用しない。
- クライアントシークレットを配布物またはローカル設定へ保存しない。

### Triage

- `gh-issues-triage <owner>/<repo>` は対象リポジトリの open Issue を新しい順に最大10件取得する。
- pull request は対象に含めない。
- Issue のタイトルと本文を Jev の `Score` プリミティブへ渡し、重要度を算出する。
- Jev が返す検証済みの `score` を変換せず重要度として使用する。
- 重要度の降順で Issue を表示して終了する。
- 同じ重要度の場合は、取得時の新しい順を維持する。

### 表示

- 結果は `重要度`、`番号`、`Issues` の3列を持つ罫線付きテーブルで表示する。
- テーブル全体の表示幅は実行時のターミナル幅と一致させる。
- 各セルは上寄せ、左寄せとする。
- 外枠以外の縦罫線 `│` の左右には半角空白を1文字ずつ置く。
- タイトルを本文より先に表示し、本文は同じセル内で折り返す。
- 複数行にわたる行では、重要度と番号を先頭行にだけ表示する。

## 品質要求

- GitHub、TypeSafe、認証情報保存の失敗を成功として扱わず、原因を標準エラー出力へ示して非ゼロで終了する。
- GitHub と TypeSafe の API キー、アクセストークン、デバイスコードをログまたは結果テーブルへ出力しない。
- API のタイムアウトとレート制限を無期限待機にしない。
- 日本語、絵文字、全角文字を含むタイトルと本文でも、表示幅をバイト数ではなく端末上の文字幅で計算する。

## 受け入れ条件

- 未認証状態から `login` を実行し、Device Flow の案内を経て認証を保存できる。
- 認証済み状態で `<owner>/<repo>` を実行すると、最大10件の open Issue が重要度順に表示される。
- pull request が混在するリポジトリでも、表示対象は Issue のみである。
- テーブル幅、配置、padding、折り返しが「表示」の要求を満たす。
- GitHub または TypeSafe の失敗時に、不完全な順位表を成功結果として表示しない。

## 制約

- 実装言語は Rust とする。
- HTTP クライアントは `reqwest` を使用する。
- GitHub の公式 API を使用する。
- 重要度判定には TypeSafe Jev の `Score` プリミティブを使用する。
