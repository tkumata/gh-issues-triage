## Goal

ユーザーが、検索の入力先と実行方法を画面内で判断できるようにする。
検索ボタンを、通常のテキストから見分けられるようにする。

## Scope

- 検索ボタンの前景色と背景色の反転。
- 検索ボタンの角括弧の削除。
- 検索入力の状態に合わせた操作案内。
- 入力欄の角括弧、空欄時の案内、入力中の枠の強調。
- 表示幅、クリック範囲、描画位置の回帰検証。
- 検索に関する正本文書と `README.md` の説明。

## Non-goals

- 検索条件、取得件数、追加 API 呼び出しの変更。
- フォーカス遷移、キー割り当て、IME 入力方式の変更。
- 検索ボタン専用のフォーカス状態の追加。
- 入力欄の複数行化、複数行の枠線、カーソル編集機能の追加。
- 新しい依存関係、設定、汎用 UI 層の追加。
- `next`、認証、Jev 判定、ブランチ作成処理の変更。

## Required Behavior

### 調査と現状

2026-10-23 に次の一次資料を確認した。

| 資料 | 観察 | 本提案への適用 |
| --- | --- | --- |
| CLI Guidelines の Ease of discovery | ヘルプや次の操作の案内で機能を発見しやすくする | 検索欄の近くに操作キーを示す |
| dialog の Built-in Bindings | Tab で編集領域とボタン等を移動する | 既存の Tab による切り替えを維持する |
| Bubble Tea の textinputs 公式例 | 入力中と非入力中の表示を分ける | 既存の入力状態表示と操作案内を対応させる |

「直感的」は、入力状態と次の操作を画面で判断できる状態とする。
資料は設計の根拠であり、本アプリの使いやすさの実証ではない。
実端末の受け入れは、実装後に別途確認する。

現状は `Keywords:` が通常表示で、`Keywords>` が入力中の表示である。
検索ボタンは、装飾のない `[Search]` である。
操作案内は、画面下部の一覧操作と同じヘルプに含まれる。
検索欄は、入力欄、ボタン、空行の3行で構成される。

### 表示案

- 入力欄は、既存の `Keywords:` と `Keywords>` を維持する。
- ボタンの文字列は、左右各1文字の空白を含む ` Search ` とする。
- ボタンは、端末の前景色と背景色を反転して表示する。
- ボタンは、角括弧を表示しない。
- ボタン右側は、半角空白を2文字置いて操作案内を表示する。
- 一覧操作中の案内は、`Tab: edit keywords` とする。
- 検索入力中の案内は、`Enter: search | Tab: list` とする。
- 案内が端末幅を超える場合、案内の末尾を切り詰める。
- ボタンと案内は、1行に収める。
- 案内と行末の余白には、反転表示を適用しない。
- ボタンの次の空行は維持する。
- 入力中の文字列は、既存どおり末尾側を表示する。
- 画面下部のヘルプは、`[Search]` を `Search` へ変更する。

通常時の表示例を示す。実画面では ` Search ` の領域を反転する。

```text
Keywords: [ Type keywords...                  ]
 Search   Tab: edit keywords

```

入力中の表示例を示す。

```text
Keywords> [ rust cli                          ]
 Search   Enter: search | Tab: list

```

### 入力欄の追加改善 (2026-10-23 承認)

ユーザーは、初回実装の実機確認を報告した。
ユーザーは、入力可能な領域が伝わらない点を追加課題とした。
ユーザーは、次の追加改善を承認した。

- 入力領域は、左右各1文字の空白を含む角括弧で囲む。
- 角括弧の右端は、端末幅の右端に揃える。
- 検索語が空文字の場合、`Type keywords...` を灰色で表示する。
- 案内の灰色は、ANSI 16色の bright black (`90`) とする。
- 案内の直後で前景色を既定色へ戻す。
- 入力した検索語と枠には、案内の灰色を適用しない。
- 案内は表示専用とし、検索語には追加しない。
- 検索語が空文字でない場合、案内を検索語に置き換える。
- 検索入力中は、左右の角括弧だけを太字で表示する。
- 太字属性は、各角括弧の直後に解除する。
- 入力中のカーソルは、表示中の検索語の直後に置く。
- 空欄時のカーソルは、案内の先頭位置に置く。
- 長い検索語は、カーソル1列分を残して末尾側を表示する。
- 案内が入力領域を超える場合、案内の末尾を切り詰める。
- `Keywords:` と `Keywords>` の切り替えは維持する。
- 入力欄、ボタン、空行の3行構成は維持する。

### 操作と互換性

- 初期フォーカスは、一覧とする。
- Tab と入力欄クリックは、既存のフォーカス遷移を維持する。
- Enter とボタンクリックは、既存の検索処理を実行する。
- ボタンのクリック範囲は、左右の空白を含む8列とする。
- 操作案内とボタン行の残りの領域は、検索を実行しない。
- 空行のクリックは、既存どおりフォーカスを変えない。
- 検索実行後は、既存どおり一覧操作へ戻る。
- 空検索、該当なし、AND 検索、再検索の動作を維持する。
- 入力中の文字と貼り付けは、既存の操作キーへ流さない。
- 検索結果からのブランチ作成対象を維持する。
- ANSI 制御列を、表示幅とクリック幅の計算に含めない。
