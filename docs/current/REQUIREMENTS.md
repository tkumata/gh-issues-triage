# GitHub Issues Triage 要求定義

## 目的

GitHub リポジトリの直近の Issue を、人が最初に確認すべき順へ並べてターミナルに表示する。

## 対象ユーザー

- GitHub リポジトリの Issue を CLI から短時間で確認したい開発者

## 機能要求

### 認証

- `gh-issues-triage <owner>/<repo>` の実行時、保存済み access token が有効ならそのまま使用する。
- access token が失効した場合は、保存済み refresh token で自動更新する。
- 認証情報が未保存、refresh token がない、または失効した場合だけ GitHub App の Device Flow を開始する。
- Device Flow では確認 URL とアクセスコードを表示し、ユーザーによるブラウザ認証の完了を待つ。
- 認証成功・更新後は、後続の実行で利用できるよう認証情報を保存して Issue 取得を続ける。
- GitHub App の client ID は `GITHUB_CLIENT_ID` 環境変数から取得する。
- GitHub App user access token と、発行された場合の refresh token は OS の資格情報ストアへ保存する。
- PAT と平文ファイルへの fallback は使用しない。
- クライアントシークレットを配布物またはローカル設定へ保存しない。

### Triage

- `gh-issues-triage <owner>/<repo>` は対象リポジトリの open Issue を新しい順に最大10件取得する。
- pull request は対象に含めない。
- Issue のタイトルと本文を Jev の `Score` プリミティブへ渡し、重要度を算出する。
- Jev が返す検証済みの `score` を変換せず重要度として使用する。
- 重要度の降順で Issue を表示して終了する。
- 同じ重要度の場合は、取得時の新しい順を維持する。

### 表示

- 結果は `重要度`、`番号`、`Issues` の3列を持つ罫線付きテーブルで表示する。
- テーブル全体の表示幅は実行時のターミナル幅と一致させる。
- 各セルは上寄せ、左寄せとする。
- 外枠以外の縦罫線 `│` の左右には半角空白を1文字ずつ置く。
- タイトルを本文より先に表示し、本文は同じセル内で折り返す。
- 複数行にわたる行では、重要度と番号を先頭行にだけ表示する。

## 品質要求

- GitHub、TypeSafe、認証情報保存の失敗を成功として扱わず、原因を標準エラー出力へ示して非ゼロで終了する。
- GitHub と TypeSafe の API キー、アクセストークン、デバイスコードをログまたは結果テーブルへ出力しない。
- API のタイムアウトとレート制限を無期限待機にしない。
- 日本語、絵文字、全角文字を含むタイトルと本文でも、表示幅をバイト数ではなく端末上の文字幅で計算する。

## 受け入れ条件

- 未認証状態から `<owner>/<repo>` を実行し、Device Flow の案内を経て認証を保存し、Issue を表示できる。
- 有効な access token は再認証せず使用し、失効時は refresh token で更新できる。
- refresh token がないか失効している場合だけ Device Flow を開始する。
- 認証済み状態で `<owner>/<repo>` を実行すると、最大10件の open Issue が重要度順に表示される。
- pull request が混在するリポジトリでも、表示対象は Issue のみである。
- テーブル幅、配置、padding、折り返しが「表示」の要求を満たす。
- GitHub または TypeSafe の失敗時に、不完全な順位表を成功結果として表示しない。

## 制約

- 実装言語は Rust とする。
- HTTP クライアントは `reqwest` を使用する。
- GitHub の公式 API を使用する。
- 重要度判定には TypeSafe Jev の `Score` プリミティブを使用する。

## 追加要求: Issue からのブランチ作成

- トリアージ結果の各 Issue の本文の下に、マウスでクリックできるブランチ作成ボタンを配置する。
- Jev に各 Issue を `refactor` / `fix` / `feat` / `chore` / `docs` のいずれかへ分類させ、ブランチ名の `prefix` とする。
- 各 Issue の番号から `issue-<number>` を作り、ブランチ名の後半とする。
- ローカルプロジェクトの root を設定できるようにし、設定ファイルへ保存する。指定された `<owner>/<repo>` から `owner/` を除いた `repo` と同名の `root/repo` を対象にする。
- ブランチ名は `<prefix>/issue-<number>` とし、対象プロジェクトの `main` から作成する。クリック後も CLI の作業ディレクトリと対象プロジェクトの現在のブランチは変更しない。
- 対象ディレクトリ、`main`、生成したブランチ名のいずれかが不正・不存在・競合する場合、別の場所や別名へ暗黙に切り替えない。
- Git 操作の失敗を成功として表示しない。既存の作業内容やブランチを上書きしない。

### 追加分の受け入れ条件

- 各表示 Issue の本文下に作成対象のブランチ名とクリック可能なボタンがあり、クリックした Issue のブランチだけを作成できる。
- 作成されたブランチの起点は対象プロジェクトの `main` で、名前は `<prefix>/issue-<number>` に一致する。
- Issue タイトルの言語に依存せず、当該 Issue の番号からブランチ名の後半を作れる。
- ディレクトリ不在、Git リポジトリ不一致、`main` 不在、同名ブランチ存在、分類の取得失敗、Git 操作失敗を利用者に知らせ、意図しないブランチを作らない。
- 設定した root は次回起動時も利用できる。ブランチ作成後も CLI と対象プロジェクトの作業ディレクトリ・現在のブランチは変わらない。
