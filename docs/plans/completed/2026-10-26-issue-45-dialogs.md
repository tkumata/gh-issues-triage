## Goal

検索と Issue 本文を専用ダイアログへ移す。
一覧ではタイトルを確認し、マウスで対象を選ぶ。
ブランチ作成操作は、対象の本文ダイアログに集約する。

## Scope

- `src/main.rs`: 一覧、入力、ダイアログ、作成操作の接続。
- `src/presentation.rs`: 一覧、ダイアログ、ボタン、操作領域。
- 両ファイル内の既存テストと関連するテストデータ。
- `README.md`: 表示と操作の説明。

- 本計画の承認状態と検証記録。

## Required Behavior

### 要求レベル

要求と受け入れ条件は、必須 (MUST) とする。

### 一覧と下部ボタン

- 重要度、Ready、番号、Author、Assignees、Issues を維持する。
- 日付列と日付ソートを維持する。
- Issues 列には、Issue のタイトルだけを表示する。
- 一覧から本文、ブランチ候補名、作成ボタンを取り除く。
- マウスオーバーによる仮選択を維持する。
- Issue の行を左クリックすると、対象の本文ダイアログを開く。
- 列見出しのクリックは、既存のソートを実行する。
- 一覧のスクロールは、マウスホイールだけで行う。
- 一覧下部には、`HELP`、`QUIT`、`SEARCH` を配置する。
- 隣接するボタンの間には、半角空白を1文字置く。
- 各ボタンは、反転表示でクリック対象を明示する。
- ボタンの左右の余白も、クリック対象に含める。
- `HELP` のクリックまたは `h` で、ヘルプを開く。
- `QUIT` のクリックまたは `q` で、アプリを終了する。
- `SEARCH` のクリックまたは `s` で、検索を開く。
- 従来の一覧移動、数字キー、Tab のショートカットを廃止する。
- ダイアログでは、一覧のショートカットを受け付けない。
- 検索の文字入力、貼り付け、Backspace は維持する。
- Enter と Esc の操作は廃止する。
- Ctrl+C は、端末復元を伴う終了操作として維持する。
- ブランチ状態表示と確認不能理由の表示を維持する。
- 重要度の説明を維持する。

### 検索ダイアログ

- 検索入力欄を、一覧から検索ダイアログへ移す。
- 検索ダイアログは、内容5行と上下の外枠の計7行とする。
- 内側は、タイトル、空行、入力欄と Search、空行、Close とする。
- 検索ダイアログには、`Search` ボタンを配置する。
- `Search` のクリックで検索し、検索ダイアログを閉じる。
- 検索後の一覧には、一致する Issue だけを表示する。
- 検索対象は、取得済みのタイトルと本文とする。
- 空白区切りの AND 検索と既存の大小文字規則を維持する。
- 空文字と空白だけの検索では、取得済み全件へ戻す。
- 検索では、追加の API リクエストを送信しない。
- 検索後も、現在のソート列と方向を維持する。
- 検索後は、一覧の仮選択を解除して先頭へ移動する。
- UTF-8 の分割入力と貼り付けの既存の検証を維持する。
- 検索文字列内の `h`、`q`、`s` は、入力文字として扱う。
- ダイアログの確定前は、一覧の適用済み検索条件を変更しない。

### Issue 本文ダイアログ

- ダイアログには、クリックした Issue の本文を表示する。
- ダイアログ内には、ブランチ作成ボタンを配置する。
- ブランチ作成ボタンは、反転表示で強調する。
- ボタンは、表示中の Issue だけを作成対象にする。
- 横幅は、ターミナル幅の75%とする。
- 高さは、ターミナルの高さから4行を引いた値とする。
- 横幅は外枠込みで端数を切り捨て、中央に配置する。
- 寸法不足の場合、理由を示して終了する。
- 検索とソートの後も、本文と作成対象を同じ Issue に対応させる。
- 作成の成功と失敗は、既存のエラー情報を含めて表示する。
- 作成成功後は、一覧のブランチ状態を更新する。
- 一覧へ戻る場合、検索条件とソート条件を維持する。
- 閲覧だけで戻る場合、一覧の仮選択と位置を維持する。
- 作成操作では、既存の Git 検証と失敗処理を維持する。

### ダイアログ共通と文書

- ダイアログ中の操作は、背後の一覧へ渡さない。
- 長文と Unicode は、端末の表示幅に合わせて扱う。
- 外部データの端末制御文字対策を維持する。
- 入出力の失敗は伝播し、終了時に端末状態を復元する。
- ヘルプの操作説明は、新しい操作だけに書き換える。
- 現在仕様の文書には、変更履歴として新しい節を追記しない。
- 現在仕様の文書は、合意済みの動作を正として整理する。
- UI 以外の認証、判定、JSON、Git の既存契約は保持する。
- 過去の承認記録と検証履歴は、現在仕様から除く。
- 未実装の提案を、実装済みまたは承認済みと記録しない。

## Tasks

### Task 1: 一覧と検索ダイアログの操作を変更する

- Status: completed

- Objective: 一覧の閲覧と検索の入力を分離する。
- Scope: `src/main.rs`、`src/presentation.rs` と内蔵テスト。
- Acceptance Criteria:
  - 一覧の Issues 列に、本文と作成ボタンが表示されない。
  - 下部3ボタンの表示、間隔、クリック範囲が一致する。
  - `h`、`q`、`s` が、対応する一覧操作を実行する。
  - 廃止したキーが、仮選択、一覧移動、作成を実行しない。
  - 検索確定でダイアログが閉じ、本文の一致も一覧へ反映される。
  - 検索、ソート、ホバーの対象が表示行と一致する。
  - ホイールで一覧全体が先頭と末尾の範囲内を移動する。
- Verification:
  - 描画とクリック境界を既存の描画テストで確認する。
  - 入力ルーティングと検索の状態遷移を自動検証する。
  - 空結果、検索解除、日本語、長いタイトルを確認する。
  - 最終の実端末検証は、Task 3 と結合して行う。

### Task 2: 行クリックと本文ダイアログを接続する

- Status: completed

- Objective: 本文の閲覧とブランチ作成を対象ごとにまとめる。
- Scope: `src/main.rs`、`src/presentation.rs` と内蔵テスト。
- Acceptance Criteria:
  - クリックした行の本文と作成ボタンがダイアログに表示される。
  - ダイアログの幅と高さが、確定した寸法規則に一致する。
  - 検索とソート後も、表示本文と作成対象が一致する。
  - 閉じる操作やホイールが、背後の一覧に伝わらない。
  - 作成失敗の理由を表示し、成功時だけブランチ状態を更新する。
- Verification:
  - Task 1 の一覧を使い、行座標と Issue の対応を検証する。
  - 寸法、長い本文、空本文、小さい端末の境界を検証する。
  - 作成対象の受け渡しと成功・失敗後の状態を自動検証する。
  - テストで実リポジトリにブランチを作成しない。

  - UI 以外の既存契約が、文書の整理で失われない。
  - 自動検証と実端末の検証結果を分けて記録する。
- Verification:
