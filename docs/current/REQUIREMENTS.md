# GitHub Issues Triage 要求定義

## 目的と対象

対象ユーザーは、CLI から GitHub Issue を確認する開発者とする。
アプリケーションは、確認すべき Issue を重要度順に提示する。
ユーザーは、本文を確認してローカルブランチを作成できる。
すべての要求と受け入れ条件は、必須 (MUST) とする。

## 範囲と制約

- 実装言語は Rust とする。
- HTTP クライアントには、`reqwest` を使用する。
- 対象は、指定した1つの GitHub リポジトリとする。
- Issue の更新と複数リポジトリの列挙は対象外とする。
- 認証には GitHub App Device Flow を使用する。
- 判定には TypeSafe Jev の `Score` と `Choice` を使用する。

## 機能要求

### 認証

- 保存済みの有効なアクセストークンを再利用する。
- 失効時は、保存済みのリフレッシュトークンで更新する。
- 未保存、refresh token なし、更新拒否では Device Flow を行う。
- 更新時のクライアント情報拒否でも、一度だけ再認証へ進む。
- 更新時と再認証時の失敗は、異なる文脈で表示する。
- 認証前に資格情報を削除しない。
- 認証成功後だけ保存し、保存成功後だけ再取得する。
- 再取得は一度だけとし、認証を繰り返さない。
- macOS Keychain または Linux Secret Service に保存する。
- PAT、平文の資格情報、配布物の client secret は使用しない。

### 取得とトリアージ

- PR を除く最新の open Issue を、最大100件取得する。
- 100件に達するまで、後続ページを読み取る。
- 最新の順序には、作成日時の降順を使用する。
- タイトルと本文から、重要度、ブランチ分類、Ready を判定する。
- 判定質問は、全 Issue を1つのリクエストにまとめる。
- 検証済みの重要度を変換せずに使用する。
- 初期表示は重要度降順とし、同点では取得順を維持する。
- 判定の欠落、不正、通信失敗では、全体を失敗させる。

### Ready

Ready は、仕様整理への着手可能度とする。
Ready は、実装への着手可否と重要度から独立させる。
判定には、タイトルと本文だけを使用する。
リンク先や実環境を調査済みと扱わない。

| 値 | 判定基準 |
| --- | --- |
| `Yes` | 具体的な動作や問題が分かり、機能の核心を創作せずに整理できる |
| `Needs information` | 話題や一般的な希望だけで、基本動作や判断基準が不明である |
| `Needs investigation` | 核心は分かるが、仕様整理を始める前に事実調査が不可欠である |

- 情報不足と調査必要が併存する場合、情報不足を優先する。
- 核心が不明な場合、質問の列挙だけで `Yes` にしない。
- 核心が分かる場合、詳細は未決事項として整理できる。
- 詳細には、出力項目、完了条件、再現条件、原因、実現方法を含む。
- 通常のコード調査が未実施という理由だけで調査必要にしない。

### 一覧と検索

- 一覧には、重要度、Ready、番号、Author を表示する。
- 一覧には、Assignees、日付、Issues も表示する。
- Issues 列には、タイトルだけを表示する。
- 日付列を表示し、重要度、番号、Author、日付でソートする。
- ホバーによる仮選択と、見出しクリックのソートを維持する。
- 行クリックで、対象の本文ダイアログを開く。
- 一覧のスクロールは、ホイールだけで行う。
- 行高は、折り返した各セルの最大行数とする。
- 下部には、HELP、QUIT、SEARCH を表示する。
- ボタン間には、半角空白を1文字置く。
- 一覧のキー操作は、`h`、`q`、`s` とする。
- Ctrl+C による終了は、全画面で維持する。
- 検索入力は、検索ダイアログだけで行う。
- 検索ダイアログは、内容5行と上下の外枠の計7行とする。
- Search のクリックで検索を確定し、ダイアログを閉じる。
- 検索は、取得済みのタイトルと本文の AND 部分一致とする。
- 空欄の検索で全件へ戻し、検索後もソート条件を維持する。
- ダイアログを Close で閉じた場合、未確定の検索語は破棄する。

### 本文、ヘルプ、ブランチ作成

- 本文は、端末幅の75%、端末高から4行を引いた領域へ表示する。
- 本文ダイアログ内には、強調した作成ボタンを配置する。
- 作成ボタンと Close は、長文のスクロール中も固定表示する。
- 作成対象は、表示中の Issue と一致させる。
- 作成時は、対象リポジトリとローカル main を検証する。
- 同名ブランチを上書きせず、失敗理由を表示する。
- 作成成功時は、作成したブランチへ切り替える。
- 番号列には、ローカルブランチの有無と確認不能を表示する。
- 確認不能を不存在として扱わず、理由を表示する。
- ヘルプは、現在の操作と表示の意味を説明する。
- ダイアログ内の操作を、背後の一覧に伝えない。
- 閲覧から戻る場合、一覧の状態を維持する。

### next

- Ready が `Yes` の最重要 Issue を1件だけ選ぶ。
- 同点では、GitHub の取得順を維持する。
- 結果は7項目の単一行 JSON として、末尾に改行を付ける。
- 該当なしと空の取得結果では、`null` を出力する。
- 重要度は丸めず、タイトルと本文を加工しない。
- 失敗を `null` に置き換えない。
- 認証案内とエラーは、標準エラー出力へ出す。
- 端末、root 設定、ブランチ状態を選定条件にしない。
- Issue とローカルブランチは変更しない。

## 品質・データ・運用要求

- Unicode 表示幅で描画とクリック領域を一致させる。
- 外部データの制御文字を、端末の操作として実行しない。
- 不正な入力と応答を、根拠のない既定値で補わない。
- 入出力、保存、API、Git の失敗理由を伝播する。
- タイムアウトと上限付き再試行を維持する。
- トークンと API キーを出力や公開設定に保存しない。
- 終了とエラーで、端末状態を復元する。
- 検索、ソート、仮選択、スクロールは対話セッション内に保持する。
- root だけを公開設定ファイルへ保存する。

## 受け入れ条件

- 認証、取得、判定、JSON、Git は、仕様の外部契約を満たす。
- 一覧には本文と作成ボタンがなく、行クリックで本文を開ける。
- 3ボタンの描画とクリック領域が一致する。
- 検索確定でダイアログが閉じ、本文の一致も一覧に反映される。
- 検索とソートの後も、行と本文と作成対象が一致する。
- ダイアログ内の操作が、背後の一覧を変更しない。
- 長いタイトル、本文、日本語、空結果を扱える。
- 一覧の移動とブランチ作成は、指定したマウス操作だけで実行する。
- `make check` と `make build` を実行する。
- 実端末と実 API の確認は、自動検証と分けて記録する。

## 未決事項

未決事項はない。
